# 代码规范化标准（2026-09-24 立 · 全项目适用）

> 目标：**注释简明（用途 / 原理）· 逻辑可读 · 相关功能聚团**。适用根目录 `.py` / `.sh` 与 `realtest/`。
> 进度与逐波验证记录 → `.agent/notes.md`。

## 文件头（模块 docstring / 脚本头部注释）

```
一句话定位（是什么线 / 什么工具）
──────────
用途：2~4 行 —— 干什么、为什么存在（动机与结论）。
原理：2~6 行 —— 关键机制、约束、不变量（指纹 / 种子 / 逐位一致 / 引擎路径…）。
用法：
    python xxx.py …        # 常见 2 种以上调用
⚠️ 一行一条：会静默出错 / 会崩 / 会错配数据 的坑（历史复盘去 notes.md，不留在代码里）
```

## 函数与行内注释

- 单行 docstring 说用途；「为什么」不直观时才补 1~3 行 —— 不写"怎么做"的流水账。
- 行内注释只在原理不直观处；日期 / 事件复盘 → `.agent/notes.md`。

## 聚团与可读性

- 文件内顺序：常量 → 基础工具 → 核心机制 → 组装 → 入口；同功能函数相邻。
- 分节横幅沿用 `# ---…--- 名称`（不强制统一长度）。
- 逻辑只做零风险润色（命名、拆表达式）；**控制流不重构**。

## 失败与兜底：出错就崩，不做兜底（2026-09-29 定）

**不为「万一」准备降级路径。** 错了就当场崩：抛异常 / `assert` / C++ 直接抛，绝不静默继续。

- **不攒着报**：校验/守卫遇到**第一个**坏值就抛，不要「跑完收集 N 个坏样本再抛」。
- **不做降级开关**：`--allow-unencodable` 这类「容忍坏输入继续跑」的开关一律删 —— 容忍 = 让错值进数据。
- **不用哨兵值表示失败**：`return -1` / `None` / `""` 当「编不出来」用 ⇒ 改成抛。
  ⚠️ `-1` 尤其毒：它在 numpy 里是**合法的末位下标**，会静默写错位置，比崩更坏。
- **不重复校验**：类型转换只在真边界（argv / 读文件 / 外部 JSON）做一次，下游不再查。
- 例外：**哨兵脚本**（`_chk_*.py`）的职责就是统计与报告（扫完全部场景、数出几个坏）⇒ 可以只报不抛；
  运行时路径没有这个待遇。
